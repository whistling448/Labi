Как защитить работу №1 по ФА

Здесь разобрано всё, что нужно для защиты: основы C, которые используются в ваших программах, устройство каждого задания, теория и вопросы, которые задают чаще всего. Задания идут не по номерам, а от простых к сложным.

Отмечайте разобранные разделы кнопкой «Разобрался». Отметки сохраняются в этом браузере.

План подготовки

Проверяющий не ждёт, что вы выучите код наизусть. Он проверяет, понимаете ли вы, что делает каждая строка и почему она написана именно так. Если понимать, на вопросы можно отвечать своими словами.

Что вы должны уметь по каждой задаче

  1. Собрать и запустить программу, показать правильную работу и реакцию на неправильный ввод.
  2. Пройти по main сверху вниз и рассказать, что происходит.
  3. Объяснить любую функцию: что принимает, что возвращает, какие ошибки обрабатывает.
  4. Ответить на вопросы по теории (математика задачи и конструкции языка C).
  5. Внести небольшое изменение прямо на защите. Например, добавить флаг, поменять формат вывода или условие. Такие просьбы встречаются часто, и это лучший способ проверить, что код ваш.
  6. Показать проверку через Dr. Memory для задач с динамической памятью.

Порядок подготовки

  1. Основы C и общие требования. Без них остальное не понять. Потратьте на них больше всего времени.
  2. Простые задачи: 1, 3, 9, 10. Здесь нет файлов, только арифметика и аргументы.
  3. Файлы: 4, 8, 7. Чтение и запись файлов, динамическая память.
  4. Сложные: 6, 5, 2. Переменное число аргументов, численные методы, математика.
Лучший способ учитьсяОткройте код задания рядом с этой страницей и для каждой строки задайте себе вопрос «зачем она тут?». Потом сломайте что-нибудь нарочно: уберите проверку, поменяйте условие, запустите. Посмотрите, что изменилось. Так запоминается в разы лучше, чем при чтении.
Если не знаете ответаНе выдумывайте. Скажите «не уверен, но думаю, что…» и рассуждайте вслух. Проверяющие спокойнее относятся к честному рассуждению, чем к уверенной ошибке.

Ещё можно попросить Claude устроить вам пробную защиту: он будет задавать вопросы по конкретной задаче как проверяющий и разбирать ваши ответы.

Основы C, которые нужны для защиты

Только то, что реально встречается в ваших программах.

1. Компиляция

C — компилируемый язык. Компилятор gcc превращает исходник .c в исполняемый файл .exe, который потом запускается.

gcc -std=c99 -Wall -g -o task1.exe task1.c -lm
ФлагЧто значит
-std=c99Компилировать по стандарту C99, как требует задание.
-WallПоказывать предупреждения о подозрительном коде.
-gДобавить отладочную информацию: номера строк в отчётах Dr. Memory.
-o task1.exeИмя выходного файла.
-lmПодключить математическую библиотеку (sqrt, pow, log…).

2. Аргументы командной строки

int main(int argc, char *argv[])

argc — количество аргументов, argv — массив строк с ними. argv[0] всегда содержит имя программы, поэтому реальные аргументы начинаются с argv[1].

.\task1.exe 7 -p
argc = 3,  argv[0] = ".\task1.exe",  argv[1] = "7",  argv[2] = "-p"

Все аргументы — строки. Число "7" нужно ещё перевести в long, этим занимается функция parse_long.

Возвращаемое значение main — код завершения: 0 означает успех, 1 — ошибку.

3. Типы данных и переполнение

ТипРазмер (Windows, MinGW)Диапазон
char1 байтсимвол или число −128…127
int4 байта≈ ±2.1·10⁹
long4 байта (в Linux 8)≈ ±2.1·10⁹
long long8 байт≈ ±9.2·10¹⁸
unsigned long long8 байт0 … 1.8·10¹⁹
double8 байт≈ 15–16 значащих цифр

Переполнение — результат не помещается в тип. Для знаковых типов это неопределённое поведение (может произойти что угодно), поэтому в коде мы заранее проверяем, поместится ли результат:

if (value > ULLONG_MAX / i) {   // если value * i не влезет
    return STATUS_OVERFLOW;
}
value *= i;

Проверять «после» нельзя: само переполнение уже ошибка.

4. Указатели

Указатель хранит адрес переменной в памяти. &x — адрес переменной x; *p — значение, лежащее по адресу p.

В C аргументы передаются в функцию копией. Чтобы функция могла записать результат в переменную вызывающего кода, ей передают адрес этой переменной:

Status factorial(const long x, unsigned long long *result) {
    ...
    *result = value;          // записываем по адресу
    return STATUS_OK;         // а возвращаем статус
}

unsigned long long f;
status = factorial(5, &f);   // передаём адрес f

Именно так во всех заданиях функция «возвращает» два значения сразу: результат через указатель, статус через return. Этого требует условие.

NULL — «пустой» указатель, который никуда не указывает. Разыменовать его (*NULL) — значит уронить программу, поэтому каждая функция в начале проверяет указатели на NULL.

5. Массивы и строки

Массив — подряд лежащие элементы одного типа, нумерация с 0. При передаче в функцию массив превращается в указатель на свой первый элемент, поэтому функция не знает его длину: размер передаётся отдельным параметром.

Строка в C — это массив char, который заканчивается нулевым символом '\0'. По нему функции понимают, где строка кончается.

"abc"  →  'a' 'b' 'c' '\0'      // 4 байта!
ФункцияЧто делает
strlen(s)Длина строки без '\0'.
strcmp(a, b)Сравнение: 0, если строки равны. Писать a == b нельзя: так сравниваются адреса, а не текст.
strcpy, strcatКопирование и дописывание строки. Место под результат должно быть выделено заранее.

6. Динамическая память

Когда размер данных неизвестен на этапе написания программы (длина слова в файле, размер случайного массива), память выделяют во время работы:

ФункцияЧто делает
malloc(n)Выделяет n байт. Содержимое — мусор.
calloc(k, size)Выделяет k элементов по size байт и заполняет нулями.
realloc(p, n)Меняет размер ранее выделенного блока, сохраняя данные.
free(p)Возвращает память системе.

Три обязательных правила, их проверяют всегда:

  1. Проверять результат на NULL. Если памяти нет, malloc возвращает NULL.
  2. Освобождать всё выделенное, в том числе на путях с ошибкой. Невозвращённая память называется утечкой; её и ищет Dr. Memory.
  3. realloc — через временный указатель:
new_buffer = realloc(*buffer, *capacity * 2);
if (new_buffer == NULL) {
    return STATUS_MEMORY_ERROR;   // старый *buffer цел, его можно освободить
}
*buffer = new_buffer;

Если написать buffer = realloc(buffer, ...) и realloc вернёт NULL, старый адрес потеряется, и память утечёт.

free(NULL) безопасен и ничего не делает. Поэтому в коде можно спокойно освобождать указатели, которые, возможно, не были выделены, если они изначально равны NULL.

7. Файлы

FILE *in = fopen("a.txt", "r");   // "r" чтение, "w" запись (файл очищается!)
if (in == NULL) { ... ошибка открытия ... }
int c = fgetc(in);                 // читает один символ или EOF
fputc(c, out);  fprintf(out, "%d\n", n);
fclose(in);                        // каждый открытый файл обязательно закрыть

Почему int c, а не char c? fgetc возвращает либо код символа (0…255), либо особое значение EOF (обычно −1), означающее «конец файла». В char нельзя надёжно отличить EOF от символа с кодом 255.

ferror(f) сообщает, была ли ошибка чтения, а EOF может означать и конец файла, и ошибку.

8. enum и статус-коды

typedef enum {
    STATUS_OK,              // = 0
    STATUS_NULL_POINTER,    // = 1
    STATUS_INVALID_NUMBER,  // = 2 ...
    STATUS_OVERFLOW
} Status;

enum — набор именованных целых констант. typedef даёт типу короткое имя Status. Каждая функция возвращает Status, а вызывающий код разбирает его через switch или if. Это прямое требование задания.

9. const

const запрещает менять значение. const long x — функция не изменит свой параметр. const char *str — функция не изменит символы строки. Требование задания: ставить const везде, где изменение не нужно. Это защищает от случайных ошибок и сразу показывает читателю, что функция только читает данные.

10. Перевод строки в число: strtol / strtod

errno = 0;
value = strtol(str, &end, 10);   // 10 — основание
if (*end != '\0')    → в строке есть лишние символы ("12abc")
if (errno == ERANGE) → число не помещается в long

end после вызова указывает на первый символ, который не удалось разобрать. Если строка корректная, это её конец ('\0'). atoi не используется: он не сообщает об ошибках (atoi("abc") молча вернёт 0).

11. Сравнение вещественных чисел через eps

Компьютер хранит double в двоичном виде, и большинство десятичных дробей представимо только приблизительно: 0.1 + 0.2 даёт 0.30000000000000004. Поэтому a == b для дробных чисел ненадёжно, и сравнивают так:

fabs(a - b) < eps   // a и b «равны» с точностью eps

По требованию задания eps всегда передаётся в функцию параметром.

12. Указатель на функцию

double (*f)(double)       // f — указатель на функцию, принимающую и возвращающую double
bisection(&root, cos_minus_x, 0.0, 1.0, 1e-6);   // передаём функцию как параметр

Позволяет написать один алгоритм (дихотомию, интеграл, подсчёт символов) и применять его к разным функциям. Используется в заданиях 2, 4, 5, 6.

13. Переменное число аргументов

Разобрано в задании 6.

Общие требования и как они выполнены

Почти наверняка спросят хотя бы про несколько пунктов. Вот что требуется, где это в коде и почему так.

ТребованиеКак выполнено
Не падать аварийноВсе входные данные проверяются, указатели проверяются на NULL, переполнение проверяется до вычисления, деление на ноль невозможно.
Нет exit() вне mainФункции никогда не завершают программу сами: они возвращают статус, а решает main (return 1). Иначе нельзя было бы освободить память и закрыть файлы.
Разделение логики и ввода-выводаФункции вычисляют и возвращают результат через параметры, а печатает только main или отдельные функции print_.... Например, find_multiples заполняет массив, а печатает main.
Валидация вводаКоличество аргументов (argc), формат флага, корректность чисел (strtol + end + errno), допустимые диапазоны.
Контроль памятиПроверка каждого malloc/realloc, free на всех путях выхода.
Ошибки файловПроверка результата fopen, все файлы закрываются, в том числе при ошибке.
Нет глобальных переменныхВсе данные передаются через параметры. #define — это не переменные, а константы, подставляемые до компиляции.
Статус-кодыtypedef enum { ... } Status, обработка через switch/if.
eps как параметрВсе функции, сравнивающие double, принимают eps.
constНа всех параметрах, которые функция не меняет.
Почему глобальные переменные — это плохо?

Их может изменить любая функция, поэтому трудно понять, кто и когда поменял значение. Функции с глобальными переменными нельзя использовать независимо и сложно тестировать. Передача через параметры делает зависимости явными.

Почему нельзя вызывать exit() из функции?

Программа завершится сразу, и вызывающий код не успеет освободить память, закрыть файлы или вывести понятное сообщение. Кроме того, функцию с exit() нельзя переиспользовать: она решает за вызывающего, что ошибка фатальная.

Что такое #define и чем отличается от переменной?

Это директива препроцессора: до компиляции каждое вхождение имени заменяется на текст. #define MAX_POWER 10 — просто подстановка числа 10, в памяти ничего не хранится и изменить это значение нельзя.

Зачем проверять параметры на NULL, если мы сами вызываем функцию правильно?

Функция должна быть корректной сама по себе, независимо от того, кто её вызывает. Это требование задания: валидировать все параметры функций. Защита от NULL не даёт программе упасть при ошибке в вызывающем коде.

Задание 1. Флаги и число x

task1.c · без динамической памяти

Программа получает число x и флаг, который говорит, что с числом сделать.

.\task1.exe 15 -h     кратные 15 до 100: 15 30 45 60 75 90
.\task1.exe 7 -p      7 - простое число
.\task1.exe 255 -s    F F
.\task1.exe 3 -e      таблица степеней
.\task1.exe 100 -a    5050
.\task1.exe 20 -f     2432902008176640000

Как устроен main

  1. Проверяем argc != 3: нужно ровно два аргумента.
  2. parse_long превращает строку в число.
  3. Проверяем флаг: первый символ - или /, затем ровно одна буква (flag[2] == '\0').
  4. switch (flag[1]) выбирает действие. Для каждого: вызвать функцию, проверить статус, напечатать результат.

Функции и алгоритмы

find_multiples (-h)

for (i = x; i <= 100; i += x)  →  x, 2x, 3x, ... до 100

Шаг равен x, поэтому перебираются сразу только кратные. При x ≤ 0 возвращается ошибка: при x = 0 цикл стал бы бесконечным.

check_prime (-p)

Простое — натуральное число больше 1, делящееся только на 1 и на себя. Составное — больше 1 и имеет другие делители. 0 и 1 не относятся ни к тем, ни к другим.

for (i = 2; i <= x / i; i++)   // то же, что i*i <= x, но без переполнения
    if (x % i == 0) → составное

Почему достаточно проверять до √x? Если x = a·b и оба множителя больше √x, то a·b > x. Значит, хотя бы один делитель не больше √x.

split_hex (-s)

Перевод в 16-ю систему делением с остатком: остаток от деления на 16 — младшая цифра, частное делим дальше. Цифры получаются от младших к старшим, поэтому массив потом разворачивается.

255 / 16 = 15, остаток 15 → F
 15 / 16 =  0, остаток 15 → F      итог: FF

Отрицательное число переводится через 0UL - (unsigned long)x. Так модуль вычисляется даже для самого маленького long, у которого -x не помещается в тип.

power_table (-e)

Таблица 10 × x. Каждая следующая степень — предыдущая, умноженная на основание: table[b][e] = table[b][e-1] * base. Тип long long нужен потому, что 10¹⁰ не помещается в int (максимум ≈ 2.1·10⁹).

sum_to (-a)

Формула Гаусса: 1 + 2 + … + x = x(x+1)/2. Одно из чисел x и x+1 всегда чётное, его делим на 2 до умножения, затем проверяем переполнение.

factorial (-f)

Умножаем 2·3·…·x, перед каждым умножением проверяем переполнение. 20! — наибольший факториал, помещающийся в unsigned long long, поэтому 21! даёт ошибку. 0! = 1.

Что будет, если запустить без аргументов или с тремя?

Проверка argc != 3 выведет подсказку по использованию и return 1.

Как программа проверяет, что x — именно число?

strtol разбирает строку и возвращает в end место, где разбор остановился. Если там не конец строки (*end != '\0'), значит, есть лишние символы. errno == ERANGE — число не влезло в long. Пустая строка и строка, начинающаяся с пробела, отсекаются отдельно.

Почему x / i, а не i * i ≤ x?

При x близком к максимуму long произведение i * i может переполниться. Деление переполниться не может.

Почему 1 не простое?

По определению у простого ровно два различных делителя: 1 и само число. У единицы делитель один. Иначе нарушилась бы единственность разложения на простые множители.

Как проверяется переполнение факториала?

Перед value *= i проверяется value > ULLONG_MAX / i. Если это так, произведение больше максимума, и функция возвращает STATUS_OVERFLOW до умножения.

Как сделать, чтобы -h искал кратные до 1000?

Поменять #define MAX_MULTIPLE 100 на 1000. Этот же макрос задаёт размер массива multiples, так что места хватит автоматически.

Задание 3. Уравнения, кратность, треугольник

task3.c · без динамической памяти
.\task3.exe -q 0.0001 1 -3 2     решения при всех перестановках a, b, c
.\task3.exe -m 10 5              10 кратно 5
.\task3.exe -t 0.0001 3 4 5      прямоугольный треугольник

Количество аргументов зависит от флага: для -q и -t argc должен быть 6, для -m — 4.

-q: квадратное уравнение

Коэффициенты (a, b, c) можно расставить 3! = 6 способами. Порядки перечислены в массиве orders. Одинаковые перестановки (например, при a = b) пропускаются: сравнение с уже решёнными через eps.

solve_quadratic разбирает случаи:

  • |a| < eps — уравнение не квадратное, а линейное: bx + c = 0. Если и b ≈ 0, то либо корней нет (c ≠ 0), либо подходит любое x (c = 0).
  • D = b² − 4ac. |D| < eps — один корень −b/(2a); D < 0 — нет действительных корней; D > 0 — два корня (−b ± √D)/(2a).

Результат хранится в структуре Equation: коэффициенты, тип ответа (RootsType) и корни.

-m: кратность

a кратно b, если a % b == 0. Ноль запрещён условием. Особый случай b = −1: выражение LONG_MIN % -1 в C вызывает переполнение и может уронить программу, поэтому этот случай обрабатывается отдельно (на −1 делится всё).

-t: прямоугольный треугольник

Стороны должны быть положительными. Наибольшая ставится в c, затем проверяется теорема Пифагора: |a² + b² − c²| < eps.

Зачем сравнивать a с eps, а не с нулём?

Число, введённое как 0.0000000001, на практике может быть результатом погрешности. Сравнение a == 0 для double ненадёжно, а условие задания прямо требует eps.

Почему перестановок 6, а выводится иногда меньше?

Если два коэффициента равны, некоторые перестановки дают одно и то же уравнение. Задание просит только уникальные, поэтому повторы пропускаются (is_same_coefficients).

Что такое struct?

Структура объединяет несколько полей разных типов в одну переменную. Доступ через точку (eq.a) или, если есть указатель, через стрелку (eq->a, то же самое, что (*eq).a).

Что в коде означает «+ 0.0» после формулы корня?

В double существует «минус ноль» (−0). Он появляется, например, при −0/5, и печатается как -0. Прибавление 0.0 превращает −0 в обычный 0, чтобы вывод был аккуратным.

Почему стороны сортируются перед проверкой?

Гипотенуза — самая длинная сторона, а пользователь мог ввести стороны в любом порядке (например, 5 3 4). После сортировки c — наибольшая, и формулу можно применять напрямую.

Задание 9. Случайные массивы

task9.c · malloc, qsort, бинарный поиск
.\task9.exe -10 10

Часть 1: обмен минимума и максимума

Массив из 20 элементов заполняется случайными числами из [a..b]. swap_min_max за один проход запоминает индексы минимума и максимума, затем меняет эти элементы местами через временную переменную.

Случайные числа

rand() выдаёт псевдослучайные числа от 0 до RAND_MAX. srand(time(NULL)) задаёт начальное значение по текущему времени, иначе при каждом запуске последовательность была бы одинаковой.

В Windows RAND_MAX = 32767, этого мало для больших диапазонов. Поэтому random_in_range склеивает 4 вызова в одно большое число и берёт остаток от деления на длину диапазона: a + random % (b − a + 1).

Часть 2: массив C

Размеры A и B случайные из [10..10000], поэтому память выделяется через malloc. Для каждого A[i] нужно найти ближайшее значение в B.

  1. Копия B сортируется функцией qsort за O(m log m).
  2. Для каждого A[i] бинарный поиск (find_closest) находит первый элемент ≥ A[i]. Ближайший — либо он, либо предыдущий.
  3. C[i] = A[i] + найденный элемент.

Итого O((n + m) log m) вместо O(n·m) при наивном переборе. При 10000 × 10000 это примерно 270 тысяч операций против 100 миллионов.

Как работает бинарный поиск?

В отсортированном массиве берём средний элемент. Если он меньше искомого, ответ правее, и отбрасываем левую половину; иначе отбрасываем правую. За каждый шаг область поиска вдвое меньше, поэтому шагов примерно log₂(m), для 10000 элементов около 14.

Что такое compare_ints и почему не return a - b?

qsort универсальная: она не знает тип элементов и получает функцию сравнения через указатель. Функция должна вернуть отрицательное число, 0 или положительное. a - b может переполниться (например, 2·10⁹ − (−2·10⁹)). Выражение (a > b) - (a < b) всегда даёт −1, 0 или 1.

Почему сортируется копия B, а не сам B?

Чтобы не менять исходные данные: функция получает B как const int b[] и не имеет права его изменять.

Где освобождается память?

Копия B — внутри build_array_c. A, B, C — в конце main. Если C выделить не удалось, A и B освобождаются перед выходом с ошибкой.

Почему «псевдо»случайные?

Числа вычисляются по детерминированной формуле из начального значения (seed). При одном и том же seed последовательность всегда одна и та же.

Задание 10. Числа в системе счисления

task10.c · ввод с консоли, динамический буфер
.\task10.exe
16
1A -FF 0010 7FFF
Stop

Сначала вводится основание, затем числа до строки Stop. Программа находит максимальное по модулю число и сумму, затем печатает их в исходной системе и в системах 9, 18, 27, 36.

Перевод строки в число (parse_number)

Схема Горнера: идём по цифрам слева направо, value = value * base + digit.

"1A" в 16-й:  0·16 + 1 = 1;  1·16 + 10 = 26

Перед каждым шагом проверяется переполнение. Буквы допускаются только заглавные, как требует условие; цифра должна быть меньше основания.

Перевод числа в строку (to_base)

Остатки от деления на основание дают цифры от младшей к старшей, поэтому они записываются в обратном порядке. Ведущих нулей не бывает по построению.

Тонкости

  • Модуль минимального числа. long long хранит числа от −2⁶³ до 2⁶³−1, поэтому у −2⁶³ нет положительной пары, и llabs переполнится. Функция absolute возвращает модуль как unsigned long long.
  • Переполнение суммы проверяется до сложения в add_number.
  • Слова любой длины. read_token читает слово в динамический буфер, который удваивается через realloc.
  • Некорректное число не останавливает ввод: выводится сообщение, и число пропускается.
Переведите 26 в 9-ю систему вручную.

26 / 9 = 2, остаток 8; 2 / 9 = 0, остаток 2. Читаем остатки снизу вверх: 28. Проверка: 2·9 + 8 = 26.

Почему максимальная система — 36?

Для цифр используются 10 арабских цифр и 26 латинских букв: 10 + 26 = 36.

Как проверить переполнение при value * base + digit?

Условие value > (limit - digit) / base. Если оно выполнено, результат превысит limit. Для отрицательных чисел limit на 1 больше: модуль −2⁶³ равен 2⁶³.

Что будет, если ввод кончится без Stop?

read_token вернёт STATUS_END_OF_FILE, цикл завершится, программа сообщит об этом и выведет результат по введённым числам. В консоли конец ввода — Ctrl+Z, затем Enter.

Буква n после - означает, что путь выходного файла задан третьим аргументом. Без неё имя создаётся как out_ + имя входного файла.

Как устроено

  • parse_flag разбирает флаг: определяет действие и есть ли n.
  • make_output_name вставляет out_ перед именем файла, а не перед всем путём: tests\in4.txt → tests\out_in4.txt. Для этого ищется последний / или \. Память под новую строку: длина входа + 4 символа префикса + 1 под '\0'.

  • Последняя строка без \n в конце тоже учитывается (флаг has_chars).
Почему буквы проверяются диапазонами, а не isalpha?

Нужны именно латинские буквы. isalpha зависит от локали и может считать буквами другие символы. Сравнение c >= 'a' && c <= 'z' работает, потому что латинские буквы идут в ASCII подряд.

Что такое ASCII?

Таблица, ставящая символам числа 0–127: '0' = 48, 'A' = 65, 'a' = 97, пробел = 32, перевод строки = 10. Русские буквы в ASCII не входят и в UTF-8 занимают 2 байта, поэтому с -a каждая даёт два hex-кода.

Что значит %02X?

Шестнадцатеричное число заглавными буквами, минимум 2 знака с ведущим нулём: 10 → 0A. Без этого перевод строки выглядел бы как A и сливался с соседями.

Что если входного файла нет?

fopen вернёт NULL, программа выведет ошибку, освободит память под имя выходного файла и вернёт 1.

Почему в is_special исключён '\r'?

В Windows строки заканчиваются парой \r\n. Чтобы невидимый \r не попадал в подсчёт «особых» символов, он исключён.

Задание 8. Минимальное основание

task8.c · файлы, лексемы, структура
.\task8.exe tests\in8.txt tests\o8.txt
вход: 0001 zz -7F     выход:  1 2 1 / zz 36 1295 / -7F 16 -127

Для каждого числа из файла нужно вывести само число без ведущих нулей, минимальное основание, в котором оно корректно, и его значение в десятичной системе.

Идея

Цифра должна быть меньше основания. Значит, минимальное основание = (самая большая цифра) + 1, но не меньше 2.

"7F": цифры 7 и 15 → max = 15 → основание 16
"0":  max = 0 → но оснований меньше 2 нет → 2

Как устроено

  • read_token читает слова, разделённые пробелами, табуляциями и переводами строк, в динамический буфер.
  • analyze_number: знак, проверка символов и поиск максимальной цифры, пропуск ведущих нулей (сдвигом указателя, без копирования), перевод схемой Горнера с проверкой переполнения.
  • Результат собирается в структуру Number, write_number пишет его в файл. Логика отделена от вывода.
  • Строчные и прописные буквы одинаковы: a и A — обе цифра 10.
  • При некорректной лексеме (ab#) программа сообщает, какая лексема плохая, и останавливается.
Почему у "0000" остаётся один ноль?

Цикл пропуска нулей останавливается, когда следующий символ — конец строки (*(token + 1) != '\0'). Иначе от числа осталась бы пустая строка.

Кто освобождает плохую лексему?

process_file отдаёт её через параметр bad_token, чтобы main мог её напечатать, а потом main вызывает free(bad_token). Если плохой лексемы не было, там NULL, и free(NULL) безопасен.

Какое максимальное число можно обработать?

До 2⁶⁴ − 1 (unsigned long long). Например, в 36-й системе это около 12–13 символов. Больше — ошибка переполнения.

Задание 7. Лексемы из файлов

Лексема — последовательность символов без пробелов, табуляций и переводов строк (то есть «слово»).

read_token — чтение слова любой длины

  1. Пропустить пробельные символы (isspace).
  2. Читать символы до следующего пробельного или EOF, складывая в буфер.
  3. Если буфер заполнен, удвоить его через realloc. Удвоение даёт мало перевыделений: для слова длиной 1000 их около 6.
  4. Дописать '\0'. Если ничего не прочитано — STATUS_END_OF_FILE.

Один и тот же буфер используется для всех слов и освобождается в конце.

-r: чередование

Цикл: пока хотя бы в одном файле есть слова, берём слово из первого (если есть), затем из второго (если есть). Когда один файл кончился, просто продолжают выводиться слова из другого.

a7: one two three four five   b7: A B C D E F G
→   one A two B three C four D five E F G

-a: преобразование

Нумерация лексем с 1. Порядок проверок важен: 10 делится и на 2, и на 5, поэтому «каждая десятая» проверяется первой.

Перевод в систему — деление с остатком (to_base). Коды записываются подряд, без разделителей.

Переведите 116 в 4-ю систему.

116/4 = 29 ост 0; 29/4 = 7 ост 1; 7/4 = 1 ост 3; 1/4 = 0 ост 1. Снизу вверх: 1310. Проверка: 1·64 + 3·16 + 1·4 + 0 = 116.

Как перевести заглавную букву в строчную без tolower?

В ASCII строчные буквы отстоят от заглавных на 32: 'A' = 65, 'a' = 97. В коде c - 'A' + 'a'.

Сколько памяти нужно под преобразованную лексему?

Код символа (максимум 255) в 4-й системе занимает до 4 цифр (3333), в 8-й — до 3. Поэтому выделяется длина * 4 + 1 — с запасом на любой случай плюс '\0'.

Как убедиться, что между лексемами ровно один пробел?

write_token ставит пробел перед каждой лексемой, кроме первой (флаг is_first). Поэтому лишнего пробела нет ни в начале, ни в конце.

Задание 6. Функции с переменным числом аргументов

task6.c · stdarg, рекурсия, дихотомия
.\task6.exe     все примеры встроены в main

Как работает переменное число аргументов

#include <stdarg.h>
Status polynomial(double *result, const double x, const int degree, ...) {
    va_list args;
    va_start(args, degree);              // начать после последнего обычного параметра
    for (i = 0; i <= degree; i++)
        value = value * x + va_arg(args, double);   // взять следующий аргумент
    va_end(args);                        // обязательно завершить
}

Функция сама не знает, сколько аргументов ей передали и каких они типов. Поэтому количество всегда передаётся обычным параметром (count, degree).

Самая частая ловушкаВещественные аргументы нужно передавать как 1.0, а не 1. В ... целое передаётся как int, а va_arg(args, double) прочитает его как double, и получится мусор: компилятор это не проверит. А float при передаче в ... автоматически превращается в double, поэтому читать нужно всегда double.

1. Выпуклость многоугольника

Для каждой вершины берётся векторное (косое) произведение двух соседних рёбер: cross = e1.x·e2.y − e1.y·e2.x. Знак показывает, в какую сторону поворот (налево или направо). Многоугольник выпуклый, если при обходе все повороты в одну сторону.

Дополнительно суммируются углы поворота (atan2). У выпуклого многоугольника сумма ровно 2π. Это отсекает самопересекающиеся фигуры вроде звезды: у неё повороты тоже в одну сторону, но сумма 4π.

2. Многочлен — схема Горнера

2x³ − x + 4  =  ((2·x + 0)·x − 1)·x + 4

n умножений вместо вычисления каждой степени отдельно.

3. Числа Капрекара

Число n — число Капрекара, если квадрат можно разрезать на две части, сумма которых равна n (правая часть не нулевая).

45² = 2025  → 20 + 25 = 45 ✓
297² = 88209 → 88 + 209 = 297 ✓

В коде «разрезание» делается делением: left = square / base^k, right = square % base^k для k = 1, 2, … Числа больше 2³² − 1 отклоняются, иначе квадрат не поместится в unsigned long long.

4. Среднее геометрическое

(x₁·x₂·…·xₙ)^(1/n). Перемножение может переполниться, поэтому используется логарифм: exp((ln x₁ + … + ln xₙ)/n). Отрицательные числа — ошибка (корень чётной степени из отрицательного не определён).

5. Быстрое возведение в степень (рекурсия)

xⁿ = (x^(n/2))²        если n чётно
xⁿ = (x^(n/2))² · x    если n нечётно
x⁰ = 1                 база рекурсии

Каждый шаг уменьшает n вдвое, поэтому умножений O(log n): для n = 1000 около 10 шагов вместо 1000. Отрицательная степень: x⁻ⁿ = 1/xⁿ; при x ≈ 0 это деление на ноль, и возвращается ошибка.

6. Метод дихотомии (деления пополам)

Если непрерывная функция на концах отрезка имеет разные знаки, f(a)·f(b) ≤ 0, то внутри есть корень (теорема Больцано–Коши). Делим отрезок пополам и оставляем ту половину, где знаки снова разные. Повторяем, пока длина отрезка больше eps.

Число шагов ≈ log₂((b − a)/eps). Например, для [0, 2] и eps = 10⁻¹⁰ получается около 35 шагов.

Что такое рекурсия и что такое база рекурсии?

Рекурсия — функция вызывает саму себя для меньшей задачи. База — случай, который решается без рекурсии (здесь n = 0 → 1). Без базы вызовы шли бы бесконечно, и стек переполнился бы.

Почему дихотомия требует разных знаков на концах?

Только тогда гарантировано, что непрерывная функция где-то пересекает ноль. Если знаки одинаковые, корня может не быть или их может быть чётное число, и метод не знает, какую половину выбрать. В этом случае функция возвращает STATUS_INVALID_INTERVAL, как в примере x² − 2 на [2, 3].

Почему n в fast_pow — unsigned int?

Для степени −2147483648 (INT_MIN) модуль 2147483648 не помещается в int. Перевод в unsigned int через 0U - (unsigned int)exponent корректно даёт этот модуль.

Что будет, если передать в is_convex меньше чисел, чем указано в count?

Это неопределённое поведение: va_arg прочитает мусор из памяти. У переменного числа аргументов нет проверки количества, за него отвечает вызывающий. Это главный недостаток механизма ....

Почему 1 — число Капрекара?

1² = 1 = 0 + 1: левая часть пустая (0), правая 1, сумма 1. Это стандартное соглашение.

Задание 5. Ряды и интегралы

task5.c · численные методы
.\task5.exe 0.000001 0.5      eps и x

x передаётся вторым аргументом: ряды зависят от x, а в условии не сказано, откуда его брать.

Ряды: следующий член через предыдущий

Считать каждый член по формуле, с факториалами, плохо: 171! уже не помещается в double, и это медленно. Поэтому вычисляется отношение соседних членов, и каждый следующий получается умножением предыдущего:

РядМножитель aₙ₊₁/aₙЧему равна сумма
a. xⁿ/n!x/(n+1)eˣ
b. (−1)ⁿx²ⁿ/(2n)!−x²/((2n+1)(2n+2))cos x
c. 3³ⁿ(n!)³x²ⁿ/(3n)!9(n+1)²x²/((3n+1)(3n+2))сходится при |x| < 1
d. (−1)ⁿ(2n−1)!!x²ⁿ/(2n)!!−(2n+1)x²/(2n+2)1/√(1+x²) − 1, при |x| < 1

Суммирование останавливается, когда очередной член по модулю меньше eps. Для рядов c и d проверяется |x| < 1: при |x| ≥ 1 множитель не меньше 1, члены не убывают, и ряд расходится (признак Даламбера).

Для ряда a при большом x члены сначала растут (пока n < x), поэтому условие остановки требует ещё и n > |x|. При очень больших x (например, 1000) сумма переполняет double, и выводится ошибка.

Интегралы: метод средних прямоугольников

Отрезок [0, 1] делится на n частей, на каждой высота прямоугольника — значение функции в середине части. Сумма площадей приближает интеграл.

n удваивается (1, 2, 4, 8, …), пока результат при n и при 2n не станет отличаться меньше чем на eps.

Почему именно средние прямоугольники: функция не вычисляется на концах отрезка. А там у двух функций проблемы: ln(1+x)/x при x = 0 даёт 0/0, а ln(1/(1−x)) при x = 1 уходит в бесконечность. Интеграл при этом конечен.

ИнтегралТочное значение
a. ∫ ln(1+x)/xπ²/12 ≈ 0.822467
b. ∫ e^(−x²/2)≈ 0.855624
c. ∫ ln(1/(1−x))1
d. ∫ xˣ≈ 0.783431
Что значит «вычислить с точностью eps»?

Ошибка результата должна быть не больше eps. На практике останавливаемся, когда очередное уточнение меняет результат меньше чем на eps: члены ряда меньше eps или интегралы при n и 2n отличаются меньше чем на eps.

Какие ещё есть методы численного интегрирования?

Левые и правые прямоугольники, трапеции, метод Симпсона (парабол). Симпсон точнее на гладких функциях, но вычисляет значения на концах отрезка, а здесь это опасно.

Почему у задания есть ограничение на число итераций?

Если eps очень маленький (меньше точности double, около 10⁻¹⁶), условие остановки может не выполниться никогда, и программа зависнет. Ограничение гарантирует завершение: тогда возвращается STATUS_ITERATION_LIMIT.

Что такое двойной факториал?

Произведение чисел той же чётности: 7!! = 7·5·3·1 = 105, 8!! = 8·6·4·2 = 384.

Задание 2. Константы e, π, ln 2, √2, γ

task2.c · самое математическое
.\task2.exe 0.0001

Для каждой из 5 констант три способа вычисления: предел, ряд и уравнение. Итого 15 функций с одинаковой сигнатурой Status f(double eps, double *result). В main они собраны в таблицу указателей на функции methods[5][3] и вызываются в двойном цикле.

Интересные места кода, о которых могут спросить

  • Предел для π не вычисляется «в лоб»: огромные факториалы переполнились бы. Каждое следующее значение получается из предыдущего умножением на 4n(n+1)/(2n+1)².
  • cos x = −1. Функция cos x + 1 касается нуля, но не меняет знак, а дихотомии нужна смена знака. Поэтому решается равносильное уравнение cos(x/2) = 0: так как cos x + 1 = 2cos²(x/2), корни у них одинаковые, а cos(x/2) знак меняет.
  • n — степени двойки в пределах для e и ln 2. Числа вида 1/2ᵏ хранятся в double точно, поэтому 1 + 1/n вычисляется без лишней погрешности.
  • Знакочередующиеся ряды (π, ln 2): ошибка суммы не больше первого отброшенного члена (признак Лейбница). Поэтому остановка по «член < eps» корректна, но ряды сходятся медленно: для π с eps = 10⁻⁶ нужно около 2 млн членов.
  • γ (постоянная Эйлера–Маскерони) — самая трудная. Формула-предел страдает от вычитания огромных биномиальных коэффициентов, и при m > 40 точность разрушается. Ряд сходится очень медленно. Поэтому у функций есть предел итераций, и при eps = 10⁻⁶ программа честно пишет «точность не гарантируется». Это ожидаемо, так и объясняйте.
  • Уравнение для γ использует простые числа: они находятся решетом Эратосфена в массиве на 10 млн элементов, выделенном через calloc. Это единственная динамическая память в задании.
Как работает решето Эратосфена?

Выписываем числа от 2 до N. Берём первое невычеркнутое (оно простое) и вычёркиваем все его кратные, начиная с его квадрата. Повторяем. Невычеркнутые числа — простые. Начинать с p² можно потому, что меньшие кратные уже вычеркнуты меньшими простыми.

Почему eps должен быть меньше 1 и больше 0?

При eps ≤ 0 условие «разница меньше eps» не выполнится никогда. При eps ≥ 1 результат бессмыслен: e = 2.7 ± 1 ничего не говорит.

Почему нельзя задать eps = 10⁻²⁰?

double хранит около 15–16 значащих цифр, точнее посчитать невозможно. Программа упрётся в лимит итераций и выдаст предупреждение.

Зачем у Equation второй параметр param?

Для γ уравнение e⁻ˣ = L зависит от числа L, вычисленного заранее. Глобальную переменную использовать нельзя, поэтому L передаётся в функцию уравнения через параметр. Остальные уравнения его игнорируют ((void)param подавляет предупреждение о неиспользуемом параметре).

Почему сходится итерация для √2?

Неподвижная точка g(x) = x − x²/2 + 1 удовлетворяет x² = 2. Производная g'(x) = 1 − x в точке √2 равна ≈ −0.414, по модулю меньше 1, поэтому итерации сходятся к √2 (принцип сжимающих отображений).

Dr. Memory на защите

Динамическая память есть в заданиях 2, 4, 6, 7, 8, 9, 10. Для них нужно показать, что утечек нет:

gcc -std=c99 -Wall -g -o task7.exe task7.c -lm
drmemory -suppress mingw.supp -- .\task7.exe -r tests\a7.txt tests\b7.txt tests\out.txt

В конце вывода должно быть NO ERRORS FOUND и 0 byte(s) of leak(s). Хорошо показать проверку и на ошибочном сценарии, например с несуществующим файлом: утечки часто прячутся в путях с ошибкой.

Что такое mingw.supp и зачем он?

Файл подавления известных ложных срабатываний. Dr. Memory выдаёт одно сообщение «unaddressable access» внутри стартового кода MinGW (_pei386_runtime_relocator) ещё до запуска main. Оно появляется даже у программы из одной строки printf("hi"), то есть к вашему коду не относится. Можно показать это проверяющему, запустив без -suppress.

Что такое утечка памяти и чем она плоха?

Выделенная, но не освобождённая память, на которую больше нет указателя. В короткой программе её вернёт система при завершении, но в долгой (сервер, игра) утечки копятся, пока память не кончится.

Что значит «unaddressable access»?

Обращение к памяти, которая программе не принадлежит: выход за границы массива, использование освобождённой памяти, разыменование NULL.
